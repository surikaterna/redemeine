# Saga commit intake (redemeine-fyp3.4, redemeine-fyp3.5.1)

Configure one dedicated RabbitMQ vhost **per environment** in the operator-supplied AMQP URL. Within that vhost, provision the stable names `rdm.saga.commits` (incoming durable queue), `rdm.saga.commits.dlq` (durable dead-letter queue), and `rdm.saga.commits.dlx` (durable direct dead-letter exchange). Do not suffix queue names with the environment or share this queue with another independently consuming projection/saga service: competing consumers would divide commits rather than each receiving a copy. If independent services need every commit, plan separate bound queues in a separate issue. Renaming an existing durable queue requires an explicit drain/migration plan; provisioning does not delete or repair existing declarations.

Supply the deployed Tapeworm dispatcher **headers** exchange name, exact `collection` and nonempty `partitions` to `createSagaCommitQueueTopology`. Supply `tenant` only when it exactly matches the configured `publisherTenant`; the binding uses `x-match=all` with `collection`, `partitionId`, and optional `tenant`. No `aggregateType` header is published or matched. Verify the upstream exchange configuration and publisher headers for the deployment. The source exchange belongs to the publisher: `provisionSagaTopology` asserts compatible durable headers declarations, not a new publisher contract. Broker precondition/permission errors must stop startup; use a fresh channel after a declaration failure, never consume until provisioning succeeds on that connection. Pass the returned `worker.queue` and `worker.source` to the worker on the same channel. Re-provision after reconnect, before starting the consumer.

Only messages published after a binding exists will be routed to the new queue; this does **not** recover historical commits published before provisioning. Invalid deliveries are subject to the existing worker's poison policy. Permanent failures still NACK to the DLQ; transient failures still NACK with `requeue: true` immediately. The new retry queue and publisher are **not activated by the worker** (settlement is redemeine-fyp3.5.2). No exactly-once guarantee is claimed. Inspect DLQ entries and plan safe replay separately; do not auto-delete old queues or bindings.

For the private retry topology supply a **required** positive `retryDelayMs` (integer, up to 2,147,483,647 ms; e.g. 5,000 ms) and a broker-management inspection callback `inspectRetry`. Provisioning declares durable quorum `rdm.saga.commits.retry`, direct durable `rdm.saga.commits.retry.exchange`, exact queue-name routing-key binding, queue message TTL, default-exchange DLX back to `rdm.saga.commits`, `at-least-once` dead-letter strategy and `reject-publish` overflow. Inspection must fetch queue, exchange, binding and `stream_queue` feature flag in the **same vhost** after declarations; missing inspection, permissions, conflicts and policy overrides abort readiness. Restrict publisher permissions. Do not enable retry if the operator cannot grant management inspection; there is no silent classic-queue fallback. Changing the fixed TTL or queue type on an existing queue requires a drain/migration decision, not an automatic deletion.

RabbitMQ 4.1 quorum at-least-once DLX requires the `stream_queue` feature flag, `reject-publish`, and a reachable target queue; downgrading the strategy/overflow while dead letters are pending can discard them. The pinned one-node suite tests confirmed persistence/restart/TTL routing, **not** cluster fault tolerance or all failure modes of safe DLX. Confirmed publish followed by crash before source ACK can duplicate. The input queue remains classic and its existing NACK-to-DLX path is **not** a lossless DLQ guarantee. `createSagaConfirmedRepublisher` uses its own confirm channel, mandatory routing, and persistent copies; it never ACKs the source. A return, NACK, channel loss, timeout or backpressure must leave the source unACKed and stop/pause intake rather than hot-requeue. Only redemeine-fyp3.5.2 may integrate settlement after independent full-content replay qualification.
