# Private lifecycle records v1 (`redemeine-vpwm.1`)

The executable contracts are `saga-runtime/src/turns/lifecycleWire.ts` and `lifecycleCommit.ts`. They are **not** exported by the package entry point and **not** wired to the PR111 processor/replay or Rabbit ACK path. No lifecycle record is currently persisted. The installed-consumer SDK contract remains the independently audited `redemeine-1tad` packed fixture; the new turn mapping is private and tested directly. This is a schema freeze for subsequent implementation, not a lifecycle RC claim.

| Boundary | v1 record | Invariant |
| --- | --- | --- |
| Source turn | One `saga.lifecycle.turn.v1.event` in **one physical** Tapeworm `ICommit.events[]` | `source` contains partitionId, streamId, commitId and zero-based eventIndex. Derived sourceTriggerId, sagaKey + canonical `correlateBy` instanceId (definition version excluded), routeId and deterministic commitId agree. Full resulting JSON state, ordered complete codec-validated intents (ordinal 0..n-1), exact matching schedule/cancel timer facts, optional terminal status, and pinned definitionVersion travel together. No separate marker or partial intent write. OCC sequence belongs to the commit; duplicate/ambiguous write readback must compare validated event content, ignoring only the expected OCC sequence. |
| Claim | `saga.lifecycle.progress.v1.event` with `saga.lifecycle.claim` payload, separate OCC commit | intentId and instanceId, positive claim epoch, owner and canonical expiry. Lease arbitration and recovery are future vpwm.4 work. |
| Outcome | Same progress event type, `saga.lifecycle.outcome` payload, separate OCC commit | Originating request intentId resolves the codec validator: response/error token, exact handler_data, correlation and JSON value retained. No FIFO callback inference. |
| Continuation | Same progress event type, `saga.lifecycle.continuation` payload, separate OCC commit | Originating outcome, intentId and applied/failed status retained. This is a record contract, not a callback implementation. |

New turn envelopes must be decoded before append **and** on read/replay, with full-state JSON traversal capped at 8 MiB, 32 levels and 100k nodes; each intent and outcome is independently limited to 64 KiB/16 levels by the audited codec. Whole commit traversal is also capped at 8 MiB. Unsupported versions, malformed/extra fields, reordered/missing intents, timer inconsistencies, unknown or historical local-key command names, duplicate intent IDs and unknown record types refuse processing; transport must park/quarantine rather than ACK as success or guess a migration. Registry must contain the exact aggregate creator envelope.type (`invoice.pay.command` versus overridden `billing.charge.command`), never a local key (`pay`). Definition version mismatch against pinned stream version is `definition_version_migration_unsupported`: migration/version routing is explicitly **unsupported** in the first RC until separately designed. Identical sagaKey/correlation across versions identifies the same instance, not a new stream.

PR111's `instanceCreated`, `sourceEventObserved`, `businessStateRecorded` and `intentLifecycleRecorded` remain state-only/history events. Their existing validator/projector does **not** interpret them as new lifecycle turns or executable intents; future .2/.3 must add explicit version dispatch and reject or park unknown lifecycle envelopes. No executor, firing timers, external effects, exactly-once guarantee or live write path is present here.
