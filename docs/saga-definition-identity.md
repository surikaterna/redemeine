# Private saga DefinitionIdentityV1 (development contract)

Registration produces `{ sagaKey, definitionVersion, policySha256 }`. The key is the normalized SDK saga key; the version is a positive safe integer. Registration requires no build artifact, file path, image, or release ID. `releaseId`, when supplied, is an opaque non-secret trace label only: it is not part of the identity and is never checked as evidence of callback equality. Do not pass secrets in it.

`policySha256` is lowercase hex SHA-256 of UTF-8 bytes of the ASCII prefix `redemeine.saga.definition-policy.v1\n` followed by compact `JSON.stringify([plugins, tokens, commands, schemas])`. `plugins` are `{key,version,actions}` sorted by key; `version` is the declared string or `null` when absent; `actions` are `[name,interaction]` pairs sorted by name, with interaction `fire_and_forget` or `request_response`. `tokens` are sorted `[key,phase]` pairs for response/error/retry. `commands` are the sorted canonical command allowlist. `schemas` are sorted `[id,positiveIntegerVersion]` pairs **only** for explicitly declared schemas; no inferred payload shape is fingerprinted. All names are nonempty, at most 256 UTF-16 code units, without ASCII control characters. Lists have at most 256 entries each, duplicate names/keys/IDs are rejected, and the serialized policy is at most 64 KiB. Invalid phases, interactions, versions and policy data are rejected. Neither callback source nor closure captures, secrets, or incidental manifest descriptions enter the digest. The domain and serialization are frozen as v1; changing the algorithm requires a new identity version.

Vectors: empty policy: `91e619e5861f13fa7f105384cd7fde3a6fcb06ecf5be86f88311632f91133412`; the multi-plugin/token/command/schema vector is pinned in `definition-identity.test.ts`.

**Operational rule:** bump the saga definition version for *every* behavior change, including callback, handler, build, trigger, parser or closure-capture changes, even when the policy fingerprint remains unchanged. Park existing streams until an explicit migration policy is approved. Same-process registration checks references and policy for mutation; closure captures are not inspected. Across process restarts a different callback with the same key, version and policy is **not detectable** by this identity. It is not code attestation or a cryptographic safety boundary. Initial single-node RC acceptance of this limitation requires separate lifecycle qualification and explicit operator signoff; do not claim restart-safe enforcement. The later Docker image gate (fyp3.2) must verify the *actual built artifact/image* digest against an independent deployment manifest before intake, but cannot retroactively prove callback identity and does not replace version bumps.

This registration contract is private and does not activate a worker or persistence. vpwm.2 must persist and compare identity with new initial commits, and refuse/park legacy version-only streams unless an explicit migration is approved. No ACK/write is safe on a missing or mismatched persisted identity.
