# Private saga state-turn replay bounds (`redemeine-7hd4`)

The private Mongo reader uses the writable saga partition's **unique** `(streamId, commitSequence)` index. `load` captures one high watermark; all subsequent pages use that boundary and contain complete physical commits (at most 64 and 12 MiB BSON). A commit is never split to fill a page. An append after capture is ignored until an OCC conflict causes a fresh attempt. Replay validates every commit through the captured watermark before reconciling a historical turn. The processor keeps one replay context, current aggregate state, at most one cloned pre-target state and one target commit; it does not collect stream history.

The existing business-state JSON validation remains **8 MiB** per authoritative state on new initial/`.on` turns and on stored replay. The aggregate's retained recent windows and counters have a separate **12 MiB** JSON budget; generated readonly projector records are measured after their source values have passed JSON validation. The registered identity/correlation and metadata are limited by their stored event envelopes. A copied pre-target state is budget-checked before cloning. These are memory/shape bounds, not an 8 MiB limit on the entire aggregate.

An individual stored event may be at most **10 MiB BSON**, and a complete physical commit (including Tapeworm/Mongo fields such as `_id`, token and timestamps) at most **12 MiB BSON**, leaving at least 4 MiB below Mongo's document limit. The page budget is also 12 MiB. A JSON-safe business state below 8 MiB may still be refused if source observation plus state and commit envelope exceed the independent physical cap. New commits are checked before `partition.append`; historical rows are checked before deep validation or page retention. The existing per-instance read/append policy is **1,000,000 commits / 1 GiB persisted BSON**, not a million-turn processing latency or throughput guarantee.

The opt-in `SAGA_AGGREGATE_MILLION_STRESS=1 SAGA_AGGREGATE_STRESS_COMMITS=4096` gate accounts for one lazy 64-commit page, final/current state, captured pre-target state and candidate commit, reporting sample byte counts. Its counters are manual retained-reference accounting, **not** GC or heap measurements. The separate lazy million-commit indexed-reader proof measures the reader only; a prior million-*aggregate* attempt timed out after 300 seconds and is not a pass. Longer aggregate throughput qualification requires a separate decision if an RC latency requirement is introduced. These private state-only turns do not enable start handlers, intents or effect execution.
