## Application bundle input

Provide `PROJECTION_DEFINITIONS_MODULE=/app/definitions/definitions.mjs`, an absolute normalized path to one readable regular1..4MiB `.mjs` file mounted read-only. Symbolic paths (including symlink ancestors) are refused. There is no fixture fallback, default application, package installer, registry loader framework, reload, or arbitrary CLI argument support. Missing/invalid inputs exit78 before host-owned driver constructors/connections/provisioning/consumption.

The named export `registrations` is an array1..64 of existing SDK `LiveRegistration<TState>` values. Names and event keys are bounded ASCII identifiers (`A-Z/a-z/0-9/:/./_/-`,128 characters); names are unique. Each entry uses `initialization:'suffix_contributions'`, `routing:'event_stable_commutative'`, callable state factory/identity/handlers, an aggregate descriptor, and an actual empty subscriptions array. Joins/reverse subscriptions must be absent or empty. Unknown registration/definition/stream/dedupe/hook fields refuse rather than silently changing meaning. Inline `in_document` is default; explicit `own_record` is preserved; `none` is unsupported. Hooks support callable `afterEach`; optional warning thresholds are positive safe integers<=1e9 and advisory only. Identity returns one nonempty string<=512 or actual `[]`, never arbitrary fanout.

`packages/projection-service/examples/definitions.ts` is a copyable typed Ledger/Credited example using the actual SDK shape. The test build emits a standalone `.mjs` and declarations to demonstrate typing/loading; it is not included in the worker image or used by default. Prebundle your own application/dependencies into the one input file, for example with a separately available esbuild tool:

```sh
esbuild definitions.ts --bundle --platform=node --format=esm --target=node22 --outfile=definitions.mjs
```

The input is **trusted code, not a sandbox**. Module evaluation and reducers must be synchronous, side-effect-free, suffix-valid and event-derived; no top-level await, environmental dependency or transitive application import is supported by contract. Node built-ins remain trusted-code capabilities. The loader does not prove transitive isolation, purity or bounds on synchronous execution; module-authored side effects are outside the no-host-I/O promise. State/commit JSON and live routing checks remain runtime responsibilities. Reducers/factories are never executed to validate registration structure.

At callback invocation, the private adapter rejects returned Promises/thenables from factories, identity, handlers and hooks. Refusal occurs within the synchronous projection turn before business-state append, coverage advancement or ACK; already admitted source floors remain retained. Late rejection is observed without awaiting unsupported work. This cannot cancel application-authored tasks or side effects. Ordinary synchronous handlers/hooks may return ignored nonthenable expressions (including numeric assignment results); factories and identity retain existing state/target validation. Closed structural validation includes nonenumerable own fields; supported nonenumerable fields are preserved, while symbols/accessors remain refused without invoking getters. The module exports only `registrations`; native ESM's intrinsic `Symbol.toStringTag` is accepted only for actual Node module namespaces, not authored symbolic properties.

Loading hashes bounded bytes and file/path identity before and after import, using a content-hash URL cache key. Changed bytes/inode or an asynchronous load exceeding the original CONNECT_TIMEOUT_MS deadline refuse; late failures are observed and cannot start the host. A module keeping owned timers or unresolved top-level await can be terminated with exit78 on the main invalid-load path. There is no permission to mutate a live bundle: mount it read-only and restart only under the supported ownership/reconciliation contract.
